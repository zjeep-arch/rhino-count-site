>> 九、AI 安全洞察

1. 监管从「自愿协议」转向「强制取证」

核心发现：FTC 于 10 月 14 日向 OpenAI、Anthropic 发出每份 50 余页的民事传票并将强制作证，多州同日以消费者保护起诉 OpenAI；406 名科学家联名要求对高危模型默认物理隔离。9 月底白宫的自愿协议刚签完两周，强制的信息调取就已上桌。

趋势建议：把「安全审计轨迹与事件上报机制」纳入 AI 供应商尽调清单；安全文档正在成为前沿模型的出货门槛，审计留痕能力决定发布节奏。

2. 浏览器成为 AI 时代的「新端点」

核心发现：CrowdStrike 收购 Seraphic、Zscaler 收购 SquareX、Palo Alto 推出 Prisma Browser，三家一周内同时加码；插件与恶意代码在浏览器内执行、AI agent 加剧风险，提示词级告警与 agent 行为可见性成为标配诉求。

趋势建议：在终端安全基线中补齐浏览器侧的 AI 使用可见性、数据防泄漏与提示词级告警；把「影子 AI 发现」纳入常态化治理。

3. 开源大权重 + 长上下文成为智能体基建标配

核心发现：Meta 以开放权重发布 816B 参数、1M 上下文的 Muse Spark Open，Modal、Together AI、vLLM 当日上线，Apple 演示 Mac Studio 集群本地运行。开源侧在推理、编码等可验证维度与闭源快速收敛，部署与定制的主动权回到企业一侧。

趋势建议：评估自托管开源大模型与 API 调用的成本、合规 trade-off；对数据敏感场景，本地化部署路线值得认真测算。

4. 万级 Agent 实测把「红队常态化」变成发布前标配

核心发现：Third Moment 每次大规模仿真前都用 Daybreak 驱动红队 agent 做全自动渗透测试；OpenAI 把 Daybreak 拆分为 Blue/Red 两版，Red 版专攻授权渗透测试。智能体的能力规模上去后，安全测试必须从「人工抽查」变为「机器对机器」的常态化对抗。

趋势建议：在 Agent 系统的 CI/CD 中加入自动化红队环节；把沙箱逃逸测试作为 agent 上线的硬性门禁。

5. 云厂商把智能体安全做成云原生默认能力

核心发现：阿里云「智能体安全中心」9 月正式商业化；火山引擎推 AI Trust 安全体系、华为云有智能体卫士覆盖 agent 开发部署运行。云厂商正在把围栏能力下沉为平台默认项，Shadow AI 发现、agent 行为审计成为云安全采购的新评估维度。

趋势建议：选云与 AI 平台时，把「智能体安全默认策略」的覆盖度与可审计性纳入评估清单，不要只看模型能力参数。
